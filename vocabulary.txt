# talkey context / style prompt
#
# whisper's ONLY vocabulary mechanism is this "initial prompt" - there is no
# separate lexicon to load. It is used when TALKEY_VOCAB_PROMPT=1 (now the
# default, since the server runs large-v3-turbo, which is robust enough to
# accept it). talkey applies it ONLY to dictations shorter than TALKEY_VOCAB_MAX_S
# seconds - see the length caveat below.
#
# IMPORTANT - how whisper prompts actually work (this bit us hard):
#   * The prompt sets the STYLE to imitate and seeds a few proper nouns; it does
#     NOT force words. Write a couple of NATURAL sentences in the style you
#     actually dictate - clean technical English, questions and instructions.
#   * A comma-separated WORD LIST is the WRONG format. A long word-list is an
#     "odd style atypical for a transcript" and destabilises the decoder - it can
#     make it DROP whole sentences (proven: a ~150-token list ate 3 sentences).
#     Natural prose is safe; a term dump is not.
#   * Seed ONLY the few proper nouns whisper genuinely gets wrong (project names,
#     tool names, odd acronyms). It already spells "TypeScript", "Kubernetes"
#     etc. fine, and a growing term list just drifts back toward the word-list.
#   * Keep it SHORT - only the last ~224 tokens are used.
#   * Even well-formed, a prompt is carried as context through the WHOLE clip,
#     so the more speech it is applied to the more words it can quietly reword
#     ("worktree select box" came back as "worktrees like box"). That is why
#     talkey caps it at TALKEY_VOCAB_MAX_S: short commands get the jargon fix;
#     long-form dictation stays raw and safe. Clip LENGTH is not the problem -
#     whisper handles any length; see "long dictations" in the README.
# Lines starting with # are ignored.
